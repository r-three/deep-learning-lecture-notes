Lecture 1: Introduction, Linear & Logistic Regression

Lecture 1: Introduction, Linear & Logistic Regression

Overview. This lecture begins by comparing traditional software, which is generally rule-based; machine learning, which learns patterns and behavior from data; and deep learning, a branch of machine learning that focuses on training neural networks. We then build up two linear models, linear regression and logistic regression, that serve as building blocks for everything else in this course. Specifically, we introduce linear models from the perspective of deep learning in order to present the core concepts of loss functions, gradient descent, and the chain rule for differentiation.

Motivation

Rule-based software

Consider the task of classifying handwritten images as 0 or 1. This task is simple enough that it can mostly be solved with a simple heuristic rule: a 0 almost always has at least two dark pixels crossing its middle row whereas a 1 has just one. This can be hard-coded by hand, producing something like the following:

n_dark = 0
for pixel in middle_row:
    # Assume pixel values range from 0-255
    if pixel < 100:
        n_dark += 1
if n_dark > 1:
    return 0
else:
    return 1

This simple program might work acceptably well for 0 vs 1 classification, but what about classifying all ten handwritten digits? One could start by trying to enumerate different heuristic rules to distinguish the digits, but the wide range of writing styles and possible digit positions and shapes quickly makes a rule-based system intractable. More complex problems–even those that we might consider “simple” like classifying an image as being a picture of a cat or dog–are clearly out of reach.

Machine learning

How can we design computer programs for problems that are too complex to allow for simply writing down a set of rules? In this case, while we might not be able to come up with a rule set, we may be able to come up with a training set, i.e. a collection of inputs and the corresponding desired output for the program.

Definition. Machine learning produces programs whose behavior is learned from data rather than hand-coded. Given examples of desired input–output pairs, machine learning aims to automatically adjust the program to better reproduce the function underlying the input-output mapping.

After collecting a training dataset, the first step in old-fashioned machine learning is to design a set of features. Features are computable measurements about the input (e.g., the number of dark pixels per row or the presence of a certain stroke pattern). We typically represent the input feature values as a feature vector \bm{x} by assembling all feature measurements for a given input into a fixed-length vector. In old-fashioned machine learning, these features are generally used with simple models, i.e. models that are constrained to have a simple structure that makes them amenable to optimization. The use of a simple model makes the success of old-fashioned ML depend heavily on the quality of hand-designed features. Designing the best feature for complex tasks like large-scale object recognition across tens of thousands of categories is challenging, and feature engineering can become the limiting factor in model performance.

Deep learning

What should we do to overcome the limits of feature engineering? Deep learning asks: If we are learning the model, why not learn the features too? In other words, instead of hand-designing features based on intuition and experimentation, perhaps we can directly learn features that are well-suited to the training data. As long as we have sufficient data and can effectively train such models, we might naturally expect this approach to work better. Indeed, since the resurgence of this basic idea in the early 2000s, deep learning has enabled a dizzying array of breakthroughs and transformative technologies.

Definition. Deep learning studies models that are big, complex, differentiable functions built by composing many small, simple, differentiable functions called layers. Because the full composition is differentiable, the parameters of every layer can be trained jointly, end-to-end, with gradient descent.

The maxim of learning as much of the modeling pipeline as possible is referred to as end-to-end learning. The composition of many small differentiable functions is itself differentiable, by the chain rule. This is critical for end-to-end training and is the foundation of backpropagation (Lecture 2).

Why Deep Learning Was Hard

The core techniques underlying deep learning, such as neural networks and gradient descent, have existed since the 1950s. If deep learning is so powerful, why wasn’t it the prevalent approach to machine learning until recently? For old-fashioned ML with fixed features and a simple classifier, the training loss is often convex as a function of the parameters. This means that, under benign assumptions, gradient descent is guaranteed to find the minimum, and we can be reasonably confident that the solution generalizes well to unseen data. In deep learning, we have no such guarantees. In practice, the loss is highly non-convex, and can be riddled with local optima, saddle points, and flat regions. As a result, small errors in training can lead to large errors at test time.

Historically, this made deep networks impractical. However, for the past few decades, a series of innovations have made deep learning feasible. Discussing these innovations will be the main subject of this course.

Innovation Role
Regularization Prevents overfitting; steers toward solutions that generalize
Better architectures Inductive biases tailored to data types (CNNs, Transformers, …)
Adaptive optimizers Address poor curvature in non-convex losses
Pre-training Initialize on large related tasks before the target task
Hardware (GPUs/TPUs) Massively parallel matrix computation
Large datasets Reduce overfitting; allow complex models to generalize

Linear Regression

For the rest of this lecture we study two foundational linear models.

Definition. Linear regression is a model that predicts a scalar value from an input feature vector. The prediction is an affine function of the features, meaning that any change in a feature always produces a constant, proportional change in the output.

As a running example, consider the task of predicting a home’s sale price from three features: its age (years), the square footage (sqft), and the number of bedrooms (nbr).

\hat{y} = w_1 \cdot \text{age} + w_2 \cdot \text{sqft} + w_3 \cdot \text{nbr} + b

where w_1, w_2, and w_3 are the weights assigned to each feature value and \hat{y} is the predicted price. The features can be combined into a feature vector \bm{x} = [\text{age},\, \text{sqft},\, \text{nbr}]^\top \in \mathbb{R}^4 and weights into the weight vector \bm{w} = [w_1, w_2, w_3]^\top \in \mathbb{R}^3, giving the standard expression for a linear regression model:

\hat{y} = \bm{w}^\top \bm{x} + b

The weight vector \bm{w} and bias value b are the parameters of the model. Together we write them as the parameter vector \bm{\theta} = (\bm{w}, b). In general, the parameters \bm{\theta} of a given model are the values that are tuned via optimization and “learned” from data.

What if we want to process more than one example at a time? As we will discuss later, this is common during both training and inference, or “test time”, when the trained model is being used to make predictions. We can assemple N feature vectors into a matrix \bm{X} \in \mathbb{R}^{N \times d} and compute the model’s predictions as

\hat{\bm{y}} = \bm{X}\bm{w} + b, \qquad \hat{\bm{y}} \in \mathbb{R}^N, \quad \bm{X} \in \mathbb{R}^{N \times d}

The loss function

Given a model, we need a way to tune the parameters to fit the data. To determine how well the model fits the data (and ultimately as an objective to be optimized), we use a loss function. For regression (predicting a scalar value) a common loss function is the *squared error loss**:

\mathcal{L}(\hat{y}, y) = \frac{1}{2}(\hat{y} - y)^2

where y is the true label for the input \bm{x} used to produce the prediction \hat{y}. The \frac{1}{2} is included for convenience because it will cancel out the exponent of 2 when we differentiate. The goal is to find \bm{\theta} that minimizes \mathcal{L} over the training set.

Note

In the past, you may have fit linear regression via the closed-form solution \bm{w}^* = (\bm{X}^\top \bm{X})^{-1}\bm{X}^\top \bm{y} that arises when analytically finding the minimum of the loss function. In this course, we ignore the closed-form solution and instead use gradient descent because it generalizes to neural networks whereas a closed-form solution does not.

Gradient descent

Gradient descent is the core optimization algorithm used in deep learning. Gradient descent is an iterative algorithm where, at each step, we move the parameters in the direction that most rapidly decreases the loss. As long as the function being optimized is not too complex and as long as we don’t move too much, we can be confident that we’ve decreased the loss. If we do this over and over again, we might hope to reach a minimum of the function.

Gradient Descent

Initialize parameters \bm{\theta} (we will discuss how to do this later!).

Repeat until a stopping criterion is met: \bm{\theta} \leftarrow \bm{\theta} - \eta\,\nabla_{\bm{\theta}}\mathcal{L}

where \eta > 0 is the learning rate and \nabla_{\bm{\theta}}\mathcal{L} is the gradient of the loss with respect to \bm{\theta}.

There are many ways to decide when to stop performing gradient descent. Since loss functions are generally nonnegative, a natural criteria is to wait until the loss reaches zero, but this is only possible if the model can perfectly fit the data. In the case of a linear model, this would mean that the input-output relationship is perfectly linear, which is rarely the case. Otherheuristics used as stopping criteria include:

  • The loss stops decreasing, or its rate of decrease gets sufficiently slow.
  • Performance on held-out validation data stops improving.
  • We run out of compute budget or patience.

Apart from the stopping criteria, to use gradient descent we must also specify a learning rate. Broadly, the learning rate dictates how quickly optimization progresses. However, as mentioned above (and as we will discuss further later), the gradient at a given location is only a local property of the function. Too large of a learning rate can therefore prevent gradient descent from making reliable progress and can even cause divergence, where the loss increases. Overall, we strive for a “just right” learning rate where the loss steadily decreases.

}

Computing the gradients: the chain rule

Performing gradient descent requires \nabla_{\bm{\theta}} \mathcal{L}, or in the case of linear regression, \nabla_{\bm{w}}\mathcal{L} and \frac{\partial \mathcal{L}}{\partial b}. For a differentiable model, we can compute these conveniently by applying the chain rule, which treats \mathcal{L} as a composition of functions.

For example, when computing the loss of a single training example (\bm{x}, y) using linear regression, we have

\hat{y} = \bm{w}^\top \bm{x} + b, \qquad \mathcal{L} = \tfrac{1}{2}(\hat{y} - y)^2

If we consider \mathcal{L} as a function of \hat{y} and \hat{y} as a function of \bm{w} (or b) and apply the chain rule, we have

\frac{d\mathcal{L}}{d\bm{w}} = \frac{d\mathcal{L}}{d\hat{y}} \cdot \frac{d\hat{y}}{d\bm{w}}, \qquad \frac{d\mathcal{L}}{db} = \frac{d\mathcal{L}}{d\hat{y}} \cdot \frac{d\hat{y}}{db}

We can compute these derivatives individually as \dfrac{d\mathcal{L}}{d\hat{y}} = \hat{y} - y, \qquad \dfrac{d\hat{y}}{d\bm{w}} = \bm{x}, \qquad \dfrac{d\hat{y}}{db} = 1

Substituting in these individual derivatives, we have

\nabla_{\bm{w}}\mathcal{L} = (\hat{y} - y)\,\bm{x}, \qquad \frac{\partial \mathcal{L}}{\partial b} = \hat{y} - y

For linear regression, the gradient has a clean interpretation: the update for weight w_i is the prediction error (\hat{y} - y) scaled by the feature value x_i. In this way, features that appear more strongly in the input receive proportionally larger weight updates.

Mini-batch stochastic gradient descent

So far, we have computed the gradient of the loss for a single example. In practice it is common to compute the gradient for more than one example and update the parameters using the average gradient, like so:

\bm{\theta} \leftarrow \bm{\theta} - \frac{\eta}{B} \sum_{i=1}^{B} \nabla_{\bm{\theta}} \mathcal{L}^{(i)}

where B is called the the batch size. In the most extreme case, we could set the batch size equal to our training set size and compute the average gradient of all of the examples in our training set. However, computing the gradient for every example at every step of training might be unnecessarily expensive, as we will discuss later. More common in deep learning is therefore to draw a random sample of B examples from the training set at each iteration.

Hyperparameters

Unlike parameters like \bm{w} and b, hyperparameters are generally not learned from data but instead are set by the practitioner, typically through trial and error or heuristics. So far we have observed the following hyperparameters:

Hyperparameter Description
\eta (learning rate) Step size per gradient update
Batch size B Number of examples per gradient update
Stopping criterion When to stop training
Initialization scheme Starting values for \bm{w} and b

We will revisit all of these as the course progresses.

Softmax (Logistic) Regression

The goal of regression is to produce a continuous scalar value. However, many problems of interest involve assigning the input a discrete label from a set of possible class labels. Such problems are referred to classification tasks.

Labels are further distinguished by the fact that, unlike the continuous values predicted during regression, they generally are unordered. For example, there is a natural order to the value of a house because a price of $213,000 is more than $190,000. In contrast, if we are predicting whether an image contains a picture of a cat or a dog, it would not be valid to say “cat is greater than dog” (or vice versa).

To turn our running “home price prediction” example into a classification task, we could instead aim to predict whether a given home would sell above asking, below asking, or not sell. In this way, it becomes a 3-class classification problem. As before, we will aim to make this prediction from its age, square footage, number of bedrooms, and asking price.

One-hot encoding

Representing class labels as integer class IDs (e.g. 1, 2, 3) would imply some kind of ordering.. We instead represent class labels as one-hot vectors, which are length-K (where K is the number of classes) vectors with a 1 at the position of the correct class and 0s elsewhere. In the home price example, we would use the following three one-hot vectors for our classes:

\begin{aligned} \text{“below asking”} &\;\to\; \bm{y} = [1,\, 0,\, 0]^\top \\ \text{“above asking”} &\;\to\; \bm{y} = [0,\, 1,\, 0]^\top \\ \text{“not sold”} &\;\to\; \bm{y} = [0,\, 0,\, 1]^\top \end{aligned}

Note that the (Euclidean) distance between any two one-hot vectors is always 1, thereby implying no order of any kind. As we will see later, one-hot vectors can also be interpreted as a probability distribution, where a given example’s assigned class is given a probability of 1 and the remaining classes have probabilty 0.

From scores to probabilities

To make a prediction, a softmax regression model first computes a score o_j for each class via a linear transformation of the features:

\bm{o} = \bm{W}\bm{x} + \bm{b}, \qquad \bm{W} \in \mathbb{R}^{K \times d},\;\; \bm{b} \in \mathbb{R}^K,\;\; \bm{o} \in \mathbb{R}^K

For the running example (K=3, d=4), \bm{W} has 3 \times 4 = 12 entries and \bm{b} has 3, so the model has 15 parameters in all. A larger score means the model considers that class more likely. Note that each of these scores are produced in essentially the same way as the scalar output of a linear regression model. To convert the set of predicted scores to a valid probability distribution (non-negative, summing to 1), we apply the softmax function:

\operatorname{softmax}(\bm{o})_j = \frac{\exp(o_j)}{\displaystyle\sum_{k=1}^{K} \exp(o_k)}

Since \exp(o_j) \geq 0 for all j, the output values of softmax are non-negative. Additionally, we have that

\sum_j \operatorname{softmax}(\bm{o})_j = \frac{\displaystyle \sum_{j = 1}^K \exp(o_j)}{\displaystyle\sum_{k=1}^{K} \exp(o_k)} = 1

Consequently, the output of the softmax function forms a valid probability distribution. We therefore can write the full softmax regression model as

P(y \mid \bm{x}) = \operatorname{softmax}(\bm{W}\bm{x} + \bm{b})

Effectively, as a given class’ score becomes higher, the model assigns a higher probability to that class and a lower probability to the other classes.

smSoftmax = scores => {
  const m = Math.max(...scores)
  const exps = scores.map(o => Math.exp(o - m))
  const s = exps.reduce((a, b) => a + b, 0)
  return exps.map(e => e / s)
}

Cross-Entropy Loss

For linear regression, we used a squared error loss. While it is technically possible to use a squared error loss to train a softmax regression model, in practice it is much more common to use the cross-entropy loss.1

From maximum likelihood to cross-entropy

Recall that we can consider softmax regression as producing a probability distribution over clases conditioned on the input. A natural objective would therefore to be maximizing the model’s assigned probability to the true class over a dataset of labeled examples. Concretely, given N training examples \{(\bm{x}^{(i)}, \bm{y}^{(i)})\}_{i=1}^N, we can start by aiming to maximize the joint likelihood:

\max_{\bm{\theta}} \prod_{i=1}^{N} P_{\bm{\theta}}(y^{(i)} \mid \bm{x}^{(i)})

It’s typical to maximize the log likelihood instead, because the logarithm is a monotonic function (so the parameter values corresponding to the maximum doesn’t change when you apply it) and because a product of probabilities can cause underflow and other numerical instabilities. Additionally, in machine learning we generally minimize a loss rather than maximize an objective. This leads to the minimization of the negative log-likelihood:

\min_{\bm{\theta}} -\sum_{i=1}^{N} \log P_{\bm{\theta}}(y^{(i)} \mid \bm{x}^{(i)})

We can write this in the following eqvuialent form:

\min_{\bm{\theta}} -\sum_{i=1}^{N} \sum_{j=1}^{K} \bm{y}_j^{(i)} \log P_{\bm{\theta}}(y^{(i)} \mid \bm{x}^{(i)})

by noting that \bm{y}^{(i)} is one-hot. This final equation is the cross-entropy loss, a quantity from information theory that measures how “wrong” a probability distribution is relative to the ground truth.

We can express the cross-entropy loss of for a single example using the softmax regression model with scores \bm{o} = \bm{W}\bm{x} + \bm{b} and one-hot label \bm{y} as

\begin{aligned} \mathcal{L}(\bm{y}, \hat{\bm{y}}) &= -\sum_j y_j \log \frac{\exp(o_j)}{\sum_k \exp(o_k)} \\ &= \sum_j y_j \log \sum_k \exp(o_k) - \sum_j y_j o_j \\ &= \log \sum_k \exp(o_k) \;-\; \sum_j y_j o_j \end{aligned}

where the simplifications come from the quotient rule of the logarithm and the fact that \sum_j y_j = 1. To perform gradient descent, we only need one additional term compared to those used in linear regression: \frac{d\mathcal{L}}{do_j}. The reexpression above makes \frac{d\mathcal{L}}{do_j} straightforward to derive:

\begin{aligned} \frac{d\mathcal{L}}{do_j} &= \frac{d}{do_j}\!\left[\log \sum_k \exp(o_k)\right] - y_j \\ & = \frac{\exp(o_j)}{\sum_k \exp(o_k)} - y_j \\ &= \operatorname{softmax}(\bm{o})_j - y_j \\ &= \hat{y}_j - y_j \end{aligned}

which can be expressed in vector form as \nabla_{\bm{o}} \mathcal{L} = \hat{\bm{y}} - \bm{y}. Intuitively, the gradient of the cross-entropy loss for the softmax regression model is simply the gap between the predicted probability and the ground-truth label. When the model assigns all of its probability to the correct label, the gradient is zero; but as the model becomes more incorrect, the gradient increases.
