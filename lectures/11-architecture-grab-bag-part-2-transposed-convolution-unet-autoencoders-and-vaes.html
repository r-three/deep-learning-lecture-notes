Lecture 11: Architecture Grab Bag, Part 2 — Transposed Convolution, the U-Net, Autoencoders, and VAEs

Lecture 11: Architecture Grab Bag, Part 2 — Transposed Convolution, the U-Net, Autoencoders, and VAEs

Overview. We continue pulling things out of the architecture grab bag. The bulk of this lecture is the variational autoencoder (VAE), a deep generative model built on top of the autoencoder, which we motivate through unsupervised representation learning. We will build the objective piece by piece — a reconstruction term and a regularization term — then show that the same objective falls out of a probabilistic model when we apply variational inference, and finally work through the practical choices that make it trainable, including the reparameterization trick. After that come two smaller topics that follow from wanting an autoencoder of images: the transposed convolution, a convolution-like operation that makes feature maps larger, and the U-Net, an encoder-decoder architecture for producing an output image the same size as the input. The variational autoencoder material stands on its own; the transposed convolution then grows out of the idea of a convolutional autoencoder, and the U-Net is built on the transposed convolution.

Representation Learning

It helps to motivate the variational autoencoder through representation learning, which has in some sense already been a focus of this course. In old-fashioned machine learning, we design a set of features by hand, collect them on our data, and train a simple classifier on those feature values. In deep learning, we instead feed raw data into a neural network and ask the network to learn features that are useful for the task. When we say we are learning features, we can equally say we are learning representations of the data.

So far, that representation learning has been an accidental side effect of supervised training: we build a network, train it with labels, and useful representations emerge along the way. But we can also pursue representation learning more broadly, and in particular unsupervised representation learning, where finding a representation useful for downstream tasks is the explicit goal of a stage that uses no labels at all.

With unlabeled data it is not obvious what the objective should be. One way to write one down is this: we want a representation that contains as little information as possible about the input, while still allowing us to reconstruct the input. Put differently, we want to compress the salient information about the input into a small representation, so that there is as little information in it as possible, yet still recover the original input in a perceptually accurate way. This pairing — compression and reconstruction — is the framing we will formalize.

An example makes the idea concrete. Suppose our data is 32 \times 32 binary images of handwritten digits, each pixel either black (0) or white (1). How much information does one image contain? We can measure information by storage: there are 32 \times 32 = 1024 bits in each image. The question representation learning asks is whether we can find a representation that takes far fewer than 1024 bits to store, yet still reconstructs the image accurately.

Consider what such a representation might encode. Which digit is it — a 0 through 9? That takes about four bits. How thick are the strokes? Perhaps a handful of thickness levels. How slanted is it, left or right? For a 1 specifically, does it have the little flag at the top, or the base at the bottom? Each of these is a salient factor, and if we encode the answers to enough of them, we can produce a reconstruction that looks much like the original — most importantly of the same digit, since an image of a zero is plainly different from an image of a one. Written down and encoded, these factors likely take fewer than 1024 bits.

The payoff is that a representation which compresses these salient factors is often more useful for downstream tasks than the raw data. If the representation already encodes the digit’s identity — because identity is the most salient factor for reconstruction — then a small classifier reading that representation can classify the digit easily, whereas reading the digit off the raw pixels is exactly the kind of thing that is hard to do by hand (Lecture 1). This can feel like a chicken-and-egg problem: how can a representation encode digit identity without being trained on labels? But clustering is a familiar example of uncovering class structure without supervision, so there is reason to hope that a good compression-and-reconstruction objective can surface salient factors on its own. Informally, then, the most salient factors for reconstruction are often the most useful for downstream tasks.

This is not the only route to unsupervised representations. Masked language modeling, which produced the BERT embeddings used on an earlier homework (Lecture 8), looks nothing like compression-and-reconstruction and is also unsupervised. But compression-and-reconstruction is one effective way to formalize the problem, and — as we will see — it needs no labeled data.

Autoencoders

The architecture we use to attempt this is the autoencoder. It takes an input \bm{x} — say, one of the binary handwritten images — and passes it through a sequence of layers that produce representations which get smaller and smaller, then through a further sequence of layers that make the representations bigger and bigger, until the final layer maps back to the dimensionality of the input. The output is a reconstruction of the input, which we write \tilde{\bm{x}}.

The shrinking half is the encoder; the growing half is the decoder. The smallest representation in the middle is the bottleneck, more commonly called the latent code, conventionally written \bm{z} \in \mathbb{R}^d.

Definition. An autoencoder is a neural network composed of an encoder that maps an input \bm{x} to a low-dimensional latent code \bm{z} and a decoder that maps \bm{z} back to a reconstruction \tilde{\bm{x}} of the input. It is trained to make the reconstruction close to the input.

We train the autoencoder with a reconstruction loss, for example the squared error between the input and its reconstruction:

\mathcal{L} = \lVert \bm{x} - \tilde{\bm{x}} \rVert^2.

This is an unsupervised loss: there are no labels involved. Given a data point, we feed it through the autoencoder, obtain an output, and drive down the reconstruction error. If we drive it to zero, we have preserved enough information through the bottleneck to reconstruct the original input.

Reconstruction was one of our two goals. The other was compression. Are we compressing? A natural thought is that if we make the latent code smaller than the input — \bm{x} is 1024-dimensional, say, and \bm{z} only 16-dimensional — then \bm{z} holds fewer numbers, and so surely less information. But is that actually true?

It is not. Suppose the latent code is real-valued, \bm{z} \in \mathbb{R}^d. How much information can a vector of real values hold? In principle, an infinite amount: a single real number can take infinitely many distinct values — there are infinitely many reals between any two — and we have d of them. (On a computer we of course use finite-precision floating point, so a float64 latent stores at most 64 d bits. But even setting hardware aside, the conceptual problem stands.) So making \dim(\bm{z}) < \dim(\bm{x}) does not by itself guarantee compression.

Warning

Why not just make the latent discrete? If real values are the problem, we might make \bm{z} binary — say 16 bits, holding at most 16 bits of information. The trouble is that discreteness in the middle of the model blocks gradients: we cannot backpropagate through a hard discrete bottleneck (we will meet the same obstacle with the reparameterization trick below). So we tackle the information problem a different way.

Variational Autoencoders

The variational autoencoder keeps the reconstruction objective but adds a term that penalizes the amount of information in the latent code. Rather than constrain the latent to be small or discrete, we let it be a large, high-precision, real-valued vector — capable of storing plenty of information — and then regularize the model so it uses as little of that capacity as it can. You may set \bm{z} to whatever you like for a given input, but the more information \bm{z} carries about \bm{x}, the more you are penalized. The question is how to write that penalty down.

The objective

To measure and constrain information in the latent, we turn \bm{z} into a random variable. The encoder no longer outputs a single latent code; it outputs the parameters of a probability distribution over latent codes, conditioned on the input. We write this distribution q_\phi(\bm{z} \mid \bm{x}) and call it the encoder. This is the same move the language model makes when it outputs the parameters of a categorical distribution to sample the next token from (Lecture 6): feed in \bm{x}, get a distribution, sample \bm{z} from it.

The decoder is likewise probabilistic. We treat \bm{x} as a random variable and let p_\theta(\bm{x} \mid \bm{z}) be a distribution over inputs given a latent code. So the full path is: take \bm{x}, feed it through the encoder q_\phi to get a distribution over \bm{z}, sample a \bm{z}, feed that through the decoder p_\theta to get a distribution over \bm{x}. For reconstruction, we want that final distribution to place high probability on the original \bm{x}.

The regularization term should measure how much information \bm{z} carries about \bm{x}. The natural tool is the KL divergence, which measures the extra information needed to encode samples from one distribution if you have another. We take the KL divergence between the encoder q_\phi(\bm{z} \mid \bm{x}) and a prior p(\bm{z}) — a distribution over latents that is unconditional on \bm{x}, carrying no information about any particular input. If this KL divergence is small, then drawing from q_\phi(\bm{z} \mid \bm{x}) is nearly the same as drawing from the unconditional prior, so q_\phi carries little information about \bm{x}. The only additional information in q_\phi(\bm{z} \mid \bm{x}) beyond the prior is \bm{x}, so this KL is a measure of the information used to encode \bm{x}.

Putting the two terms together — and noting that this is an objective we maximize, not a loss we minimize — the VAE objective is:

\underbrace{\mathbb{E}_{\bm{z} \sim q_\phi(\bm{z} \mid \bm{x})} \big[\log p_\theta(\bm{x} \mid \bm{z})\big]}_{\text{reconstruction}} \;-\; \underbrace{\operatorname{KL}\!\big(q_\phi(\bm{z} \mid \bm{x}) \,\big\|\, p(\bm{z})\big)}_{\text{regularization}}.

The first term is a reconstruction term in disguise. When the decoder p_\theta(\bm{x} \mid \bm{z}) — also called the likelihood model — is an identity-covariance Gaussian, its log density is, up to constants, the negative squared error between \bm{x} and the Gaussian’s mean. The density of a Gaussian carries a factor e^{-\lVert \bm{x} - \bm{\mu} \rVert^2 / (2\sigma^2)}; with unit variance the exponent is a negative squared error, and taking the log leaves exactly that. So maximizing \mathbb{E}[\log p_\theta(\bm{x} \mid \bm{z})] under a Gaussian likelihood is minimizing mean squared error between the input and the decoder’s mean. The second term, as discussed, loosely measures the information in \bm{z} about \bm{x}.

The two terms are in genuine tension, which is why this is an objective worth optimizing rather than a triviality. Reconstruction would be easiest if \bm{z} carried a great deal of information about \bm{x} — in the extreme, if the encoder simply copied \bm{x} into \bm{z}, reconstruction would be trivial. But then the KL divergence between q_\phi(\bm{z} \mid \bm{x}) and the information-free prior would be enormous, and the regularization term would be badly penalized. The objective balances the two.

At this point, if you are content to take the two terms on faith, you have everything you need to train a VAE: an architecture (two neural networks), an objective (the one above), a dataset, and an optimizer. But we can go deeper and ask what probabilistic model underlies this generative model, and show that the objective is not arbitrary — it falls out of an analysis.

A probabilistic model and the ELBO

By a probabilistic model we just mean the process by which we suppose data points are generated. The autoregressive language model’s process was: sample x_1, then x_2 given x_1, then x_3 given x_2, x_1, and so on. The VAE’s generative process is:

\bm{z} \sim p(\bm{z}), \qquad \bm{x} \sim p(\bm{x} \mid \bm{z}).

Conceptually: to draw a new handwritten digit, first sample the salient factors — which digit, how thick the pen, how much slant, whether the 1 has its flag — all encoded in \bm{z}, then sample an image conditioned on those factors. This is not so far from how a person decides what to draw before drawing it.

Having written down a probabilistic model, the maximum-likelihood framework asks us to maximize the probability the model assigns to the data we actually observed. We tune the parameters \bm{\theta} of p_\theta so that it assigns high probability to the real data points on hand — exactly as the language model was trained to assign high probability to real sequences of text (Lecture 6). Being precise, we maximize \mathbb{E}_{\bm{x} \sim p(\bm{x})}[\log p_\theta(\bm{x})] over \bm{\theta}; below we use the shorthand \log p(\bm{x}) for a single data point.

Under the generative model, we can write \log p(\bm{x}) by marginalizing out the latent:

\log p(\bm{x}) = \log \int p(\bm{x} \mid \bm{z})\, p(\bm{z}) \, d\bm{z}.

This looks like the start of an objective, but it is intractable. To evaluate it we would have to consider every possible value of \bm{z}, compute p(\bm{x} \mid \bm{z}) for each, weight by p(\bm{z}), and sum — and with continuous \bm{z} that is a sum over infinitely many possibilities. Much of generative modeling is about approximating this marginalization or constraining the model so that it is tractable. We use one such approximation: variational inference.

Variational inference does something that on its face seems trivial: to maximize a quantity, we instead maximize a lower bound on it. If some other quantity is always \le \log p(\bm{x}), then pushing that lower quantity up tends to push \log p(\bm{x}) up as well. An easy way to build a lower bound on any quantity is to subtract something non-negative from it, and the KL divergence is always non-negative. So we subtract a KL divergence:

\log p(\bm{x}) \;\ge\; \log p(\bm{x}) - \operatorname{KL}\!\big(q_\phi(\bm{z} \mid \bm{x}) \,\big\|\, p(\bm{z} \mid \bm{x})\big).

The right-hand side is the evidence lower bound (ELBO). The distribution q_\phi(\bm{z} \mid \bm{x}) it introduces is the approximate posterior — our encoder. Maximizing the ELBO simultaneously pushes up the data probability \log p(\bm{x}) and pushes the approximate posterior toward the true posterior p(\bm{z} \mid \bm{x}) (Kingma and Welling 2014; Rezende et al. 2014).

As written, the ELBO is still not something we can optimize: it contains \log p(\bm{x}), which we cannot compute, and the true posterior p(\bm{z} \mid \bm{x}), which we also do not have. The remaining work is algebra — no further approximations. Write the troublesome KL divergence using its definition,

\operatorname{KL}\!\big(q_\phi(\bm{z} \mid \bm{x}) \,\big\|\, p(\bm{z} \mid \bm{x})\big) = \mathbb{E}_q\big[\log q_\phi(\bm{z} \mid \bm{x})\big] - \mathbb{E}_q\big[\log p(\bm{z} \mid \bm{x})\big],

and rewrite the true posterior with Bayes’ rule, p(\bm{z} \mid \bm{x}) = \dfrac{p(\bm{x} \mid \bm{z})\, p(\bm{z})}{p(\bm{x})}. Substituting into the second term and using \log of a product/quotient as a sum/difference of logs,

\mathbb{E}_q\big[\log p(\bm{z} \mid \bm{x})\big] = \mathbb{E}_q\big[\log p(\bm{x} \mid \bm{z})\big] + \mathbb{E}_q\big[\log p(\bm{z})\big] - \underbrace{\mathbb{E}_q\big[\log p(\bm{x})\big]}_{\log p(\bm{x})}.

The last term simplifies because \log p(\bm{x}) has no \bm{z} in it, so the expectation over \bm{z} leaves it unchanged. Substituting all of this back into the ELBO, the two \log p(\bm{x}) terms cancel — and \log p(\bm{x}) was exactly the term we could not compute:

\log p(\bm{x}) \;\ge\; \underbrace{\mathbb{E}_q\big[\log p_\theta(\bm{x} \mid \bm{z})\big]}_{\text{reconstruction}} \;-\; \underbrace{\operatorname{KL}\!\big(q_\phi(\bm{z} \mid \bm{x}) \,\big\|\, p(\bm{z})\big)}_{\text{regularization}}.

Every distribution here is one we have access to: the encoder q_\phi, the decoder p_\theta (which we model, replacing the intractable p(\bm{x} \mid \bm{z})), and the prior p(\bm{z}). This is exactly the objective we wrote down earlier — applying variational inference to the VAE’s generative model recovers it.

VAEs in practice

Nothing in the derivation requires neural networks, but in practice the encoder and decoder are neural networks, and we train them by gradient-based learning. Since we are maximizing an objective, this is gradient ascent — \bm{\theta} \leftarrow \bm{\theta} + \eta \nabla_{\bm{\theta}}(\cdot), a plus rather than a minus — differentiating the objective with respect to every parameter and stepping to increase it. The standard practical choices are:

  1. The encoder and decoder q_\phi(\bm{z} \mid \bm{x}), p_\theta(\bm{x} \mid \bm{z}) are neural networks.
  2. The prior p(\bm{z}) is a zero-mean, identity-covariance Gaussian — the default uninformative choice.
  3. The approximate posterior q_\phi(\bm{z} \mid \bm{x}) is a diagonal-covariance Gaussian.

The third choice fixes what “output the parameters of a distribution” means concretely. If \dim(\bm{z}) = d and q_\phi is a diagonal Gaussian, the encoder must output 2d numbers: d for the mean \bm{\mu} and d for the diagonal of the covariance. A mean can be any real number, so those d units get no output nonlinearity. A variance must be positive, so the d variance units pass through a nonlinearity with positive outputs — a standard choice is the softplus, which resembles a ReLU but is smooth.

With a Gaussian prior and a diagonal-Gaussian posterior, the KL term has a closed form. Writing the objective’s regularization term with its sign, it becomes (up to a factor of \tfrac{1}{2})

\tfrac{1}{2}\sum_{j=1}^{d} \Big(1 + \log \sigma_j^2 - \mu_j^2 - \sigma_j^2\Big),

which we are maximizing. The -\mu_j^2 term is maximized at \mu_j = 0, pulling each mean toward the zero-mean prior. The remaining 1 + \log \sigma_j^2 - \sigma_j^2 is maximized at \sigma_j = 1, pulling each variance toward the identity-covariance prior. So the optimum of the KL term is \bm{\mu} = \bm{0}, \bm{\sigma} = \bm{1} — exactly the prior, as it should be.

The reparameterization trick

There is one subtlety in training. To do gradient ascent we must differentiate the objective back to every parameter, and the parameters live in both the decoder and the encoder. But between them the computational graph contains a sampling operation: the decoder is not fed the encoder’s outputs \bm{\mu} and \bm{\sigma} directly — it is fed a sample \bm{z} \sim q_\phi(\bm{z} \mid \bm{x}) drawn from the distribution those outputs parameterize. We have never before had a sampling operation inside a computational graph, and it is not obvious how to backpropagate through one.

The fix is the reparameterization trick, and you have likely used its core idea already. If your random number generator only produces samples from the standard normal \mathcal{N}(\bm{0}, \bm{I}), how do you sample from a Gaussian with a different mean and covariance? You draw standard-normal noise, scale it by the standard deviation, and shift by the mean. We do exactly that: instead of sampling \bm{z} from q_\phi(\bm{z} \mid \bm{x}) directly, sample noise from the prior and transform it,

\bm{\epsilon} \sim p(\bm{z}) = \mathcal{N}(\bm{0}, \bm{I}), \qquad z_j \leftarrow \mu_j + \sigma_j\, \epsilon_j.

This solves the problem by moving the stochasticity out of the path we need to differentiate. The sample \bm{\epsilon} is now an input — noise that, as far as the gradients are concerned, is constant — and \bm{z} is a deterministic, differentiable function of the encoder’s outputs \bm{\mu} and \bm{\sigma}. Backpropagating with respect to \bm{\mu} and \bm{\sigma} is then routine: we are just scaling and shifting noise. We do not ignore the noise — it is what makes the output equivalent to having sampled directly — but it no longer disrupts our ability to compute gradients.

The reparameterization trick works for Gaussians but not for every distribution. You cannot reparameterize sampling from a discrete distribution this way — the same obstacle that ruled out a discrete bottleneck. When you must differentiate through a discrete sample, you fall back on an approximation such as the Gumbel-softmax (concrete) relaxation (Jang et al. 2017), which smoothly approximates the discrete sample, or on a score-function estimator of the REINFORCE type; these are gradient estimators, trading off bias and variance (Gumbel-softmax is low-variance but biased; REINFORCE is unbiased but high-variance).

Note

The likelihood model should match the data. We took the decoder p_\theta(\bm{x} \mid \bm{z}) to be a Gaussian, which turned reconstruction into mean squared error — a reasonable assumption when the data values are roughly Gaussian. For binary black-and-white images it is a poor fit: a pixel’s values are bimodal (0 or 1), not Gaussian. There, the likelihood model should be a Bernoulli distribution, and the reconstruction term becomes a cross-entropy rather than a squared error. The choice of likelihood model is an assumption about the distribution of values in the data.

Transposed Convolution

Suppose we want a convolutional autoencoder of images. In the encoder we replace the sequence of MLPs with convolutional layers — appropriate for images, since convolutions bring translation invariance and locality (Lecture 5) — and with striding or pooling the spatial size shrinks, taking a 32 \times 32 input down to, say, a 4 \times 4 \times 8 activation volume that serves as the latent code. But the decoder must map back up to 32 \times 32. Every convolution we have seen so far makes feature maps smaller (through striding, padding, and boundary effects); we have no convolution-like operation that makes them bigger. The transposed convolution is that operation, and it has been lurking implicitly since we introduced convolutional networks.

Start from an ordinary convolution. Let \bm{x} be a 4 \times 4 image and \bm{k} a 2 \times 2 kernel, and apply a stride-2 convolution to get a 2 \times 2 output \bm{y}. A convolution is a linear operation, so it can be written as a matrix multiply. Flatten the input image into a vector with \operatorname{vec}(\cdot) (stacking rows, say), and there is a convolution matrix \bm{C} with

\bm{C}\, \operatorname{vec}(\bm{x}) = \operatorname{vec}(\bm{y}), \qquad \bm{C} \in \mathbb{R}^{4 \times 16}.

Here \bm{C} maps the 16-dimensional flattened input to the 4-dimensional flattened output. Each row of \bm{C} holds the kernel entries k_{00}, k_{01}, k_{10}, k_{11} placed in the positions that one output pixel reads from, with zeros everywhere else — so \bm{C} is mostly zeros. We could implement any convolution this way, as an explicit (if wasteful) matrix-vector product.

The transposed convolution is what happens when we transpose that matrix. Take a 2 \times 2 input \bm{z}, and multiply by \bm{C}^\top \in \mathbb{R}^{16 \times 4}, which maps a 4-dimensional input to a 16-dimensional output — a 4 \times 4 image:

\bm{C}^\top \operatorname{vec}(\bm{z}) = \operatorname{vec}(\bm{y}), \qquad \bm{C}^\top \in \mathbb{R}^{16 \times 4}.

So where a stride-2 convolution took 4 \times 4 to 2 \times 2, the corresponding transposed convolution takes 2 \times 2 back up to 4 \times 4. Working out what \bm{C}^\top does to \bm{z} gives a useful mental picture: each entry z_{ij} of the input multiplies the whole kernel, and the result is pasted into the output at the corresponding location. Take z_{00}, scale the kernel by it, paste; move to z_{01}, scale the kernel, paste; and so on across the input.

Definition. A transposed convolution applies the transpose \bm{C}^\top of a convolution’s matrix \bm{C}. Equivalently, it pastes a copy of the kernel into the output for each input entry, scaled by that entry, summing where copies overlap. With a stride, it increases the spatial size — the inverse of the size change a strided convolution produces.

This mental picture extends to channels: a multi-channel transposed convolution pastes each channel’s kernel scaled by that channel’s input and sums the results. If one kernel looks like a cat’s face and another like a cat’s body, then an input that is one at the face location and one at the body location, and zero elsewhere, pastes the face and the body into place and sums them into a cat.

Where has the transposed convolution been hiding? In the backward pass. Recall that a dense layer’s forward pass multiplies by \bm{W} and its backward pass multiplies by \bm{W}^\top. Since a convolution’s forward pass is a multiply by \bm{C}, its backward pass is a multiply by \bm{C}^\top — a transposed convolution. It is the operation that computes gradients through a convolution, and it has been there implicitly all along.

Note

A puzzle. Given the 2 \times 2 kernel and a transposed-convolution output, can we construct an input — a few nonzero entries, the rest zero — such that an ordinary (not transposed) convolution with the same kernel produces that same output? There is an easier version where we may rearrange the kernel’s entries and a harder one where we may not. Working it through sharpens the distinction between a transposed convolution and an ordinary convolution that merely shares its kernel.

The U-Net

For images we have mostly built networks that take an image in and produce a classification. It is also useful to take an image in and produce an image out — for example, semantic segmentation, where we classify every pixel (these pixels are people, those are chairs), producing an output the same shape as the input.

Here the tension between the two size changes is exactly the point. A convolutional network that shrinks the representation is good for aggregating global information and growing the receptive field — we would like to know the scene is a classroom before deciding which pixels are people and which are chairs. But to make a dense, per-pixel prediction we then need to grow the representation back up to full resolution, which is what the transposed convolution provides. The standard architecture for aggregating global information and then upsampling to the input’s size is the U-Net (Ronneberger et al. 2015).

The U-Net has a down path of convolutions and pooling that produces smaller and smaller feature maps, and an up path of transposed convolutions that grows them back. The essential ingredient is concatenation: the feature volume produced by a convolutional layer on the down path is concatenated, along the channel axis, with the same-shaped feature volume produced by the transposed convolution on the up path. As long as the shapes match going down and coming back up, we can concatenate at each level.

Definition. A U-Net is an encoder-decoder for images: a down path of convolution and pooling that shrinks feature maps while widening the receptive field, an up path of transposed convolutions that restores the spatial size, and skip connections that concatenate each down-path feature volume with the matching up-path feature volume. It maps an input image to an output image of the same size.

The reason for the concatenation is that the down path discards local, high-resolution information as it aggregates global context. The skip connections carry that local information from the down path across to the up path, so the final layers can combine global context with local detail to make sharp per-pixel predictions. The architecture is named for its U shape when drawn. Beyond dense prediction like segmentation, the U-Net is also a workhorse of diffusion models, another family of generative models.

Summary

Note

Key takeaways from Lecture 11:

  • Unsupervised representation learning can be framed as compression plus reconstruction: encode the input with as little information as possible while still being able to reconstruct it. The salient factors for reconstruction are often the most useful for downstream tasks.
  • An autoencoder pairs an encoder \bm{x} \to \bm{z} with a decoder \bm{z} \to \tilde{\bm{x}}, trained by a reconstruction loss such as \lVert \bm{x} - \tilde{\bm{x}}\rVert^2. A smaller latent does not guarantee compression, because a real-valued vector can hold unbounded information; a discrete latent would fix that but blocks gradients.
  • A variational autoencoder makes the latent stochastic and adds a KL regularizer, maximizing \mathbb{E}_{q_\phi(\bm{z} \mid \bm{x})}[\log p_\theta(\bm{x} \mid \bm{z})] - \operatorname{KL}(q_\phi(\bm{z} \mid \bm{x}) \,\|\, p(\bm{z})). A Gaussian likelihood makes the reconstruction term a squared error (Bernoulli for binary pixels makes it a cross-entropy); the KL term measures the information the latent carries about the input.
  • The same objective is the evidence lower bound, obtained by applying variational inference to the VAE’s generative model \bm{z} \sim p(\bm{z}), \bm{x} \sim p(\bm{x} \mid \bm{z}) and cancelling the intractable \log p(\bm{x}) and true posterior p(\bm{z} \mid \bm{x}) via Bayes’ rule.
  • In practice the prior is \mathcal{N}(\bm{0}, \bm{I}), the encoder is a diagonal Gaussian outputting 2d numbers (means, and variances through a softplus), and the KL term has a closed form optimized at \bm{\mu} = \bm{0}, \bm{\sigma} = \bm{1}. The reparameterization trick z_j = \mu_j + \sigma_j \epsilon_j, \bm{\epsilon} \sim \mathcal{N}(\bm{0}, \bm{I}), moves the sampling out of the differentiated path; it does not work for discrete latents.
  • A transposed convolution applies \bm{C}^\top, the transpose of a convolution’s matrix — equivalently, it pastes the kernel into the output scaled by each input entry, and it grows feature maps. It is the backward pass of a convolution.
  • A U-Net combines a shrinking convolutional down path, a growing transposed-convolution up path, and skip connections that concatenate matching feature maps, producing an output image the same size as the input. It is used for dense prediction such as semantic segmentation, and in diffusion models.
