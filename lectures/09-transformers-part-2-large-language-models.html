Lecture 9: Transformers, Part 2, Large Language Models

Lecture 9: Transformers, Part 2, Large Language Models

Overview. In the previous lecture we built the encoder-only transformer. Here we cover two further variants and what transformers are used for. We start with the decoder-only transformer, which performs autoregressive next-token generation using the same architecture we already have, trained efficiently with a causal mask. This leads into large language models: language modeling on unlabeled text scales predictably, every text task can be cast as next-token prediction, and models are steered through prompting, in-context learning, and post-training. We then build the encoder-decoder transformer with cross-attention, note the standard conventions for a transformer’s dimensions, and close with the vision transformer, which applies the same architecture to images.

The Decoder-Only Transformer

The encoder-only transformer of Lecture 8 could classify, label, and extract from sequences, but not generate a new one. We now use a transformer for sequence generation, which in this course we have called language modeling. Earlier this meant masked language modeling, filling in blanks; here we return to the older form seen with recurrent networks — given the previous words, predict the next one.

Consider generating a sequence autoregressively. We begin with a beginning-of-sequence token, <bos>, since we need to feed the model something to start. Suppose it then predicts “the.” The only token it could have attended to when producing “the” is <bos> — nothing else exists yet. If it next produces “cat,” it could attend only to <bos> and “the”; producing “sat,” only to <bos>, “the,” and “cat.” Could it have attended to “on” while producing “sat”? No — “on” had not been generated yet. When a model with self-attention generates autoregressively, each generated token can attend only to past tokens, because the future tokens do not yet exist. (Contrast this with an encoder processing a full input sequence given up front, where any position can attend to any other, in any order — the encoder-only case.)

Drawing this as an attention matrix, where a cell is filled if that attention is allowed, gives a lower-triangular pattern: the token generated at each row attends only to itself and the tokens before it.

We have not changed the transformer at all. We feed in <bos>, run self-attention over that one token and the position-wise feed-forward networks, take the output representation, feed it into a classifier over the |V| vocabulary entries, sample from the resulting distribution, and feed the sampled token back in. We then feed in both tokens, take the output representation at the last position, sample the next token, and repeat. The architecture is untouched; only the way we use it differs.

Warning

There is no mask here (yet). One sometimes hears that a decoder-only transformer is “an encoder-only transformer with a causal mask.” That is misleading. A decoder-only transformer is the same architecture used for autoregressive generation; the causal mask, described next, is a trick for training it efficiently, not part of the architecture. Generation itself needs no mask — feeding tokens back in one at a time already attends only to the past.

Training with a causal mask

We have shown how to generate from the model but not how to train it. One could train it exactly as it is used: feed in the first token, predict the second with a cross-entropy loss, feed in the first two, predict the third, and so on. This works but is sequential, processing one token at a time. There is a trick that lets us train a decoder-only transformer for autoregressive generation entirely in parallel across sequence positions — not strictly necessary, but no one omits it, since the sequential version is far less efficient.

Suppose we feed in the full ground-truth sequence — say “the cat sat on the mat” — take the output activations, and train the model to predict “cat” at the second position. If we did this in an ordinary encoder-only transformer, the model could attend to the very word it is trying to predict and drive the loss to zero, but it would then fail at generation time, where the next word is not available. So we cannot simply feed in the full sequence and train for next-step prediction. Instead we force the model to have the attention pattern from the generation case above, by zeroing out the attention weights into the future.

Definition. A causal mask zeroes out the attention weights to future positions in self-attention. Feeding in the full sequence and applying the causal mask lets a decoder-only transformer be trained for next-step prediction in parallel across all positions, since no position can access information from the future.

Because the position-wise feed-forward networks act on each position independently, zeroing the future attention weights is enough to prevent any position from seeing the future. Training a decoder-only transformer this way is completely parallelizable across time. This is unlike a recurrent network, whose architecture is inherently sequential — computing the hidden state \bm{h}_t requires \bm{h}_{t-1} — and it was one of the properties that drew people to transformers, since the hardware we train on is built for parallel computation.

KV caching

A second observation concerns generation. Do the keys and values change as more of the sequence is generated? If we have computed the keys and values for positions 1 through 3 and then generate position 4, the keys and values for 1 through 3 do not change: they are computed from the representations at those positions, and because the causal mask prevents positions 1–3 from attending to anything at position 4 or beyond, those representations are unaffected by whatever comes later. So the keys and values do not change as the sequence grows, and we can cache them at test time — storing each key and value vector in memory and growing the cache with each new token, rather than recomputing the past. This is KV caching, and it saves computation during generation. The caveat is memory: for a very long sequence, each head in each layer must store key and value vectors as long as the sequence, which can become large.

Scaling Up: Large Language Models

The next several ideas concern language models specifically and are, in a sense, somewhat apart from core deep learning — which is about optimizers and architectures like Adam and the transformer, rather than the language model itself. But language modeling has become influential enough to be worth covering.

Unlabeled text and predictable scaling

To train a language model for next-token prediction, all we need is text: a textbook’s text is the training data, with no annotation of sentiment, topic, or translation required. We often call such data unlabeled, though the term is a slight misnomer, since the next word is in effect the label and a human did write the text. The point is that there is an enormous amount of it — people have been writing, and especially typing onto the internet, for a long time. Where an image-classification dataset might reach ten million labeled pairs with effort, in language modeling every next word is a target, and it is not hard to gather a trillion tokens of text, or ten trillion — six orders of magnitude more.

This matters because of a theme from the start of the course: deep learning’s promise is to train larger models on larger datasets. Scaling up recurrent networks was hard — vanishing and exploding gradients made larger, deeper networks unstable, and sequential training could not be mapped efficiently onto parallel hardware. Transformers tend to be more stable, for two reasons seen earlier: the path length is always one, so mixing information across time takes a single application of self-attention rather than a repeated recurrent update; and the residual connections and layer norms help stability.

So people trained transformers on text, and since there was more text, trained larger models on more of it — and the models kept improving. The finding was that scaling the model and the data leads not merely to improvement but to predictable improvement:

Plotting test loss against the number of parameters, both on log scales, gives close to a straight line, and it holds across many orders of magnitude. This is unlike most of the modeling in this course, where one cannot say in advance what the validation loss will be. It amounts to a recipe: with the compute and the data to train a larger model, one can confidently expect a lower test loss. Ongoing research largely concerns changing the slope of this line, but the line itself is a striking regularity (Kaplan et al. 2020).

Every text task is text-to-text

A lower loss on held-out data means the model is better able to predict the next token. Consider what predicting the next token can express. Given “When was Wayne Gretzky born?” a natural continuation is his birth year, so a model that predicts the next token well, in some sense, knows it. Given two sentences and “Do these two sentences mean the same thing?” the continuation “yes” or “no” is paraphrase identification. Given a long article followed by “tl;dr” — “too long; didn’t read” — the continuation is a summary, which is document summarization. Given “‘I like cheese’ in French is,” the continuation is a translation.

Any text-based task can be formulated as a text-to-text task: conditioned on a prefix \bm{x}_1, \dots, \bm{x}_{t-1}, predict the next token \bm{x}_t.

If predicting the next token can express every text-based task, then a lower loss on the full distribution of held-out text means being better at, in effect, every task — a striking implication of the scaling regularity above.

Prompting and in-context learning

There is a complication. These models are trained on unlabeled web text, where a prefix often has many reasonable continuations. “When was Wayne Gretzky born?” might be followed by “I don’t know”; “Do these two sentences mean the same thing?” by “I don’t care”; the translation prompt by an unrelated but common continuation. A lower test loss does not guarantee that the most probable continuation is the one we want. This is the importance of prompting: how we formulate the request so that the desired continuation is the most probable under the training distribution. We can try different phrasings — “[sentence] in French is…” versus “The French translation of [sentence] is…” For classification tasks, rather than generating, we can inspect the probabilities the model assigns to the tokens for each answer choice — for example, comparing the probability of “yes” to that of “no.”

A third approach is few-shot in-context learning. The examples so far were zero-shot: we describe a task and ask the model to perform it with no worked examples. If instead we can gather a small task-specific dataset, we can provide it as part of the prefix. For instance, a two-shot prompt might read “Who played Batman in the Dark Knight? Christian Bale. Who was the lead singer of the Foo Fighters? Dave Grohl. When was Wayne Gretzky born?” — the earlier question–answer pairs make the answer, rather than “I don’t know,” the more probable continuation.

Definition. In-context learning provides labeled examples of a task within the prefix, so the model performs the task without any update to its parameters (Brown et al. 2020).

In-context learning resembles learning — supplying question-answering examples improves question answering — but it does not update parameters, so the same model can be adapted to any task by changing the prompt. Its drawbacks are that the cost of prediction grows with the number of in-context examples (a longer prompt means more tokens to process), that it works only with large-ish models, and that it often works worse than fine-tuning on the same examples.

Post-training

Many uses of a large language model do not require careful prompting — one states a request and the model complies. Getting from a base model, pre-trained on web text, to one that reliably follows instructions takes further training. This class of methods is called post-training (an odd name, since a model that is pre-trained and then post-trained is never simply “trained”); these are language-model techniques rather than core deep learning, so we cover them briefly.

One common step is instruction tuning, also called supervised fine-tuning: train the model on a mixture of diverse query–response pairs spanning many tasks — writing a story, answering a homework question, classifying a tweet’s sentiment. In classical terms, if the training data samples many tasks, the test data samples other tasks, and instruction tuning improves generalization to new tasks, that is, instruction-following (Wei et al. 2022).

A second step is learning from feedback. Given a good and a bad response to the same input, train the model to make the good response more likely and the bad one less likely. This differs from ordinary fine-tuning, which only supplies good responses; here the model is told what to do more of and what to do less of. The techniques used come from reinforcement learning, so this is often called reinforcement learning from human feedback (Ouyang et al. 2022). Prompting, in-context learning, instruction tuning, and learning from feedback are all ways to elicit the behavior we want from a model whose next-token predictions were shaped by language modeling on web text.

The Encoder-Decoder Transformer

We can now build encoder-only and decoder-only transformers. The encoder-decoder transformer combines them, and was in fact the first transformer proposed, as an alternative to the encoder–decoder RNN with attention (Lecture 6). The encoder-only transformer plays the role of that RNN’s encoder — processing an input sequence with full visibility into a sequence of hidden states — and the decoder-only transformer plays the role of its decoder, autoregressively generating an output conditioned on the input.

The question is how to feed the encoder’s outputs to the decoder. In the encoder–decoder RNN we used attention, and we do the same here, adding one more attention mechanism — the encoder-decoder attention, or cross-attention — into the decoder. Filling in the five ingredients (Lecture 7):

  • Queries: the decoder states.
  • Keys: the encoder outputs.
  • Values: the encoder outputs.
  • Comparison: scaled dot product.
  • Reduction: softmax-weighted average.

This is the same as the encoder–decoder attention of the sequence-to-sequence RNN. We insert it into each decoder block, between the multi-headed self-attention and the feed-forward network, each sublayer wrapped in a residual connection and followed by a layer norm as before.

The encoder is unchanged, and the decoder differs from a decoder-only transformer only by the added cross-attention sublayer, which takes the encoder outputs as its keys and values. To train an encoder-decoder transformer, we can always use supervised sequence-to-sequence data — feed the English sentence into the encoder and train the decoder to generate the French translation, as with the sequence-to-sequence RNN. To train on unlabeled data, we use an objective similar to masked language modeling: corrupt some text by masking spans, and train the model to predict the missing parts (Raffel et al. 2020). Given “Thank you for inviting me to your party,” we might mask “for inviting” and “party” to get “Thank you <mask> me to your <mask>,” with target “for inviting <sep> party” — the two recovered spans separated by a <sep> token. Because the missing spans are generated autoregressively as an output sequence, a masked span can cover several tokens — unlike masked language modeling in an encoder-only model, where each masked position corresponds to a single token.

Note

Decoder-only or encoder-decoder for sequence-to-sequence? A decoder-only transformer can also do sequence-to-sequence tasks — the prompting above feeds in a prefix and generates a continuation. The difference is that an encoder-decoder transformer has a separate encoder stack, with its own parameters, that processes the input with full visibility, whereas a decoder-only transformer’s causal mask limits how the prefix is attended to. Both work; the encoder-decoder arrangement is arguably a more natural fit for sequence-to-sequence tasks.

Transformer Architecture Conventions

A transformer has several shape hyperparameters, and there are standard conventions for them. The main quantities are:

  • L — the number of layer blocks (the depth). “A 12-layer transformer” means 12 blocks, each with multi-headed self-attention, layer norms, residual connections, and a feed-forward network.
  • d_{\text{model}} — the dimensionality along the residual path (the width), fixed across the model and including the embedding dimension. In a pre-layer-norm transformer the residual connection goes around the whole block, so this dimension cannot change from block to block.
  • d_{\text{ff}} — the dimensionality inside the feed-forward networks, which project up to d_{\text{ff}} and back down to d_{\text{model}}.
  • d_{kv} — the dimensionality of the queries, keys, and values. Queries and keys must match, since attention uses a scaled dot product, and values are usually made the same size.
  • H — the number of attention heads. Unlike a convolutional network’s channels, these shape hyperparameters are typically fixed across all blocks.

Three conventions, none universal, are common:

d_{\text{ff}} = 4\, d_{\text{model}}, \qquad H \, d_{kv} = d_{\text{model}}, \qquad L \text{ and } d_{\text{model}} \text{ grow together}.

The feed-forward network projects into a space four times as wide before projecting back. Setting H\,d_{kv} = d_{\text{model}} makes the total size of the queries, keys, and values across all heads equal to d_{\text{model}}, so doubling the number of heads halves d_{kv}. And when scaling a model up, one typically increases depth and width together rather than only one — matching the scaling story above, where “parameters” grows along both axes.

The Vision Transformer

So far we have applied transformers only to text. A considerable time after the transformer was introduced, people found how to apply it effectively to vision, giving the vision transformer.

Recall the convolution’s inductive bias: locality and shift invariance, a reasonable structural assumption for images. The transformer has a much weaker inductive bias — only that every output may depend on every input. This is more generic and makes fewer assumptions, which may be good or bad, but it means a transformer can learn the appropriate structure rather than having it built in. Trained on a vision task, self-attention could learn locality, for instance, by attending only to a small region of the input; more generally it can learn arbitrary dependencies, especially with position encodings.

To use a transformer we need a sequence, but an image is a grid of pixels with channels. Reading pixels one at a time would give an enormous sequence — a 1024 \times 1024 \times 3 image would become a sequence of length roughly three million. Instead we split the image into patches: take each P \times P patch across all channels, flatten it into a vector, and let each patch be one sequence element.

An image of height h, width w, and C channels becomes a sequence of length m = hw / P^2 of vectors of dimension C P^2. (With P = 1 this is one pixel per element.) Each patch’s vector carries spatial context. To classify, we then follow the encoder-only recipe: map the image to a length-m sequence, prepend a <CLS> representation, and linearly project each sequence element from C P^2 to d_{\text{model}} with a learned projection — needed because C P^2 (e.g., 27 for a 3\times3 patch of a 3-channel image) is not the width we want. Everything after that is an ordinary encoder-only transformer, with the <CLS> output fed to a classifier. The transformer itself is unchanged; only the way an image is turned into a sequence is new (Dosovitskiy et al. 2021).

This works well, with one caveat: it works especially well after pre-training. Suppose we pre-train on a large dataset and fine-tune on a task of interest, and measure downstream performance as a function of the pre-training dataset size.

For a convolutional network, performance improves with the pre-training budget. For a vision transformer, performance is worse at a small pre-training budget but better at a large one. The reason is inductive bias. Pre-training teaches the model the structure of the problem — for vision, recognizing shape templates such as round, square, or striped things. A convolutional network already assumes locality and shift invariance, so it needs less pre-training to do well; a vision transformer assumes almost nothing and must learn the structure, which requires more pre-training. But locality and shift invariance are not the right structure for every vision task, so given enough pre-training, a vision transformer can learn a better structural assumption and surpass the convolutional network.

Summary

Note

Key takeaways from Lecture 9:

  • A decoder-only transformer generates autoregressively using the unchanged transformer architecture: each generated token attends only to past tokens. The causal mask — zeroing attention to future positions — lets it be trained for next-step prediction in parallel across positions, unlike a sequential RNN. KV caching reuses the unchanging keys and values during generation.
  • Language modeling trains on unlabeled text, of which there is a great deal. Scaling the model and data yields predictable improvement — test loss versus parameters is nearly linear on log-log axes.
  • Any text task is text-to-text: conditioned on a prefix, predict the next token. Lower held-out loss therefore means being better at essentially every text task. Models are steered by prompting, in-context learning (labeled examples in the prefix, no parameter updates), and post-training (instruction tuning and learning from feedback).
  • The encoder-decoder transformer adds cross-attention in the decoder — queries from the decoder, keys and values from the encoder outputs — and can be pre-trained on unlabeled text by predicting masked spans.
  • Transformer conventions: L blocks (depth), d_{\text{model}} (width), d_{\text{ff}} = 4\,d_{\text{model}}, H\,d_{kv} = d_{\text{model}}, with depth and width grown together.
  • The vision transformer splits an image into patches, projects them to d_{\text{model}}, and runs an ordinary encoder-only transformer. Its weaker inductive bias means it needs more pre-training than a convolutional network but can surpass it once pre-trained enough.
